Long sessions stay quick

Most of this release does one thing: keep a conversation that has run for hundreds of turns as fast and as accurate as it was at the start. Old tool results are put away and fetched back when needed, a full context folds its middle first and keeps the newest exchange, and a subagent's context is kept apart from the conversation's. Alongside that: session export, approvals that say what they are about, and stricter command safety.

New
- Export a session: a ZIP of the transcript, the subagents' transcripts and the files kept beside the session, from the chat or with /export in the composer, saved wherever you pick. A file too large, or one past what an export may hold, is left out and counted.
- Approvals say what they are about: each request carries a risk label (read, write, destructive, credential, network), whether the change can be undone, and where the tool comes from. Destructive and credential ones add why — that a drive's root, a system folder or the home directory is being removed, or that a key or password file is being touched. What was asked and decided goes to an audit log.
- Browser tools ask even in full access: reading a signed-in page's cookies or localStorage, or intercepting and changing its traffic, is confirmed one call at a time whatever the mode.
- See what an MCP server offers: a server's row opens to its tools, resources and prompts, and shows its last error whatever its status — enough to tell why it is not working without leaving the chat.
- Bring in what another conversation said: a message naming a saved conversation (as `[Session id: title]`, which the composer inserts) carries that conversation's newest messages, marked as background rather than instructions. At most three sources, 8000 characters each.
- What the turn changed, and what it delivered: files handed over show as a card, and the activity strip lists the files the last turn changed apart from what earlier turns left, with their line counts.
- The phone sees how full the context is: a session update may carry the window, what it holds, where compaction starts and whether it has happened. Older desktops send none, and phones that do not know the field ignore it.

Improved
- Context management for long sessions, reworked:
  - Old tool results are trimmed before they are cleared: one longer than 8K characters first keeps only its head and tail, which is often enough; only when it is not are earlier groups cleared. A resumed conversation applies the same cuts.
  - Compaction leaves room for the answer: the threshold reserves the model's answer (at most 21K) and 13K for the request, never compacting below half the window. After a summary the newest exchange is kept verbatim, a call always with its results.
  - The model can fold, search and restore its own context with tools the chat does not show — only a notice. Folding rewrites the range it covers, so the prompt cache past it stays.
  - Reminders at the 3rd, 5th and 8th identical call.
  - Tools have a deadline, WebFetch 90 seconds; a large Bash result is kept whole until the context machinery offloads it, with both ends in the placeholder.
- A subagent's context is its own: each run owns its usage, todos, read files and compaction counter, and its summary no longer enters the parent's context.
- Failures are told apart: rate limit, overload, context overflow, auth and certificate each say what to do. Small jobs — summaries, titles, classifiers — give up on an overload at once rather than retrying for minutes.
- An empty answer is asked again: a stream that never said anything is its own kind of failure, retried twice rather than spending the whole budget; a turn that ends with no text and no tool call is retried twice, then warned about.
- Compaction ratio and headroom can be set globally or per model, and prompt-too-long compaction retries are configurable (default 1).
- Dangerous commands are judged more strictly: git hard resets, cleans and forced pushes, find -delete, rsync --delete, Windows recursive deletes, and commands wrapped in sudo, env, timeout or xargs. PowerShell's abbreviated parameters (-fo is -Force), `& { }` call blocks and `$( )` subexpressions are read through, and `iex (iwr …)` — fetched and run — is recognised and offered no always-allow rule.
- Credential folders and keys are protected paths.
- A resumed session seeds its read state from the transcript; a host may seed one with seed_read_state.
- A tool call's input is no longer kept once its result is in: a Write's whole file, an Edit's two strings. Only a background command's, a subagent's and a plan's are read again.
- Search starts from the conversations that can match, through an in-memory index; a query it cannot narrow is scanned as before, so no hit is lost.
- Auto mode works on another provider's model: where Claude Code's own classifier does not run, BaoCode judges the action with the provider's small model, and the CLI is told to ask.
- A resumed session no longer overwrites the approval picked here, and the mode is re-sent when the model changes.
- Auto mode warns about allow rules that would bypass it, and a rule that would allow every command (Bash(bash:*)) is no longer offered as always-allow.
- Enhance works in an empty project: with nothing to name there, the model used to write a plan instead of the message and be turned down as too long, without a second try. It is now asked again without the project.

Fixed
- Search and session listings stay quick on very long transcripts (only the ends are read).
- A subagent's card keeps its latest 200 steps and says how many it left out.
- A proxy turned on or off mid-session reaches the CLI at once.
- Compaction stops after three failures in a row instead of spinning.
- Full access is really full access on Windows: there is no root to be there, so the CLI is no longer needlessly held at Accept edits.
