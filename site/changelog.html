Changelog

What changed in each version of BaoCode.

1.7.0

Diagnostics, bots and a smoother app

This release is mostly about knowing what went wrong and staying out of the way: a hang or a crash now leaves a report you can read and send, the interface no longer freezes for seconds at a time, and Enhance Prompt answers in a fraction of the time it took. Alongside that, bots — agents you chat with as you would a person, from your phone — and the relay that lets a phone reach this desktop from any network.

New

  • Bots: agents that chat as a person does, from your phone. Each has a name, a picture, a gender, a signature and a speaking style of its own, and a model you pick. They can see the agents' conversations, start one in a project, write to an agent as you would, read the projects' files, use the browser, make pictures, and write first when something happened — a run finished, one failed — at most a few times a day and never in your quiet hours. Their pictures and stickers show in their chats.
  • A phone from any network: a relay carries the phone's connection when the two cannot see each other, so no port to open and no public address needed. The desktop holds the relay's address and a token only it has; what crosses is sealed before it reaches the relay, which reads none of it. Settings → Mobile shows where the desktop's end stands.
  • Diagnostics: when the app hangs or a run ends badly, the event log says how it ended; on macOS the system's hang and crash reports are collected with the logs, and a stack sample is taken while the app is stuck, its Dart frames named. Send it all from Settings → Diagnostics.
  • The Git log: the graph's lanes are no longer cut at twelve, a commit's details can be selected and copied, and branch names show as they are — a local branch with a slash in its name is no longer taken for a remote one.
  • The commit panel: a check box by each change, a List | Tree switch for the file list, and a commit message written from the changes checked alone.
  • The session sidebar's file tree shows each file's Git status; a changed markdown file shows rendered, and one click switches it to its diff.
  • Mermaid diagrams in a reply are drawn, and the agent is told what the chat can render, so it writes what shows.
  • Find and search work across lines: a paste of several lines is found as it was pasted, and a search finds a phrase broken across two.
  • Zoom in, out and reset with the keyboard; the interface size change goes into the event log, with what changed it.
  • The IDE's activity bar has a settings gear at its foot.
  • The phone sees what a tool call did with pictures, what a browser step was, what the agent's goal is and how its turn is going, and when each bot message was sent.

Improved

  • No more freezes: the system proxy was read on the window's own thread, running a command there; it now runs where it cannot hold the window. The same for the processes a build and a screenshot start.
  • Enhance Prompt answers in a fraction of the time. Three of six real runs came back too long — and those were the slowest, one of them two minutes before giving up. It is now told to keep it in proportion to what was asked, and is stopped as it writes past that.
  • A large browser message no longer copies the whole buffer for every chunk: 20 MB took 5.5 seconds and now takes 0.3.
  • A reply that is copied keeps its markdown: a long paste is no longer cut down to "[Pasted text #1 +660 lines]".
  • MCP servers that answer in GBK are read correctly instead of as garbage.

Fixed

  • A model's token counts given as strings ("input_tokens": "1234") no longer throw.
  • A message being edited stays the editor's row; the copied markdown is no longer the cached bubble.
  • An input method composing over a selection replaces it, rather than leaving both.
  • A Windows browser host left reading a stale TEMP folder is found again.

1.6.0

Performance

This release is about speed and memory: in a long conversation, a reply streaming in, scrolling and dragging the minimap all keep up with you; the app holds much less memory as it runs; and on Windows the interface draws several times faster. Besides, Stash keeps in step with your projects' GitHub / GitLab issues, and an SSH connection that drops picks up the same session again, with nothing running there lost.

Performance

  • Windows draws with Skia, as macOS does, not Flutter's new default Impeller: measured, a frame of the chat takes a fraction of the time to draw, in about half the memory.
  • Long conversations stream more smoothly: each file path in a reply is no longer looked up in every file the session has read. On a real 92-turn conversation, a frame went from 6.8 ms to 4.5 ms, and janky frames from 18 to none.
  • Very long replies and thoughts let go of what is far out of view, keeping only its height, and show it again as it comes back; a thought draws only what is in view; code, tables and math scrolled sideways are kept as pictures. Select All and copying still get all of the text.
  • Dragging the minimap or the scrollbar fast no longer builds what is out of view meanwhile, catching up over a few frames after; a reply scrolled away and back is not parsed again. Dragged back and forth fast, a frame went from 12.9 ms to 2.5 ms.
  • Less memory: Skia's texture cache is held to 32 MB rather than 150 to 300 MB, and decoded images to 48 MB; on macOS large blocks freed go back to the system, some 180 MB while a long thought streams.
  • Leaner editors: files of the same language share one syntax highlighting worker, its patterns compiled once (TypeScript's 334 were compiled in some 3,500 places), and line layouts are held to about 32 MB.
  • In plan mode the prompt cache is read again: each turn wrote the whole conversation to it anew, slower and dearer.
  • A trackpad flings the editors on as it does lists; on macOS lists no longer bounce at their ends.

New

  • Stash and issues, both ways: in a project that is a GitHub / GitLab repository, open issues become stashes, one row each with its status, title, conversation and issue. Kept in step: changed there, taken here; changed here, pushed once you confirm; changed on both sides, yours to pick; an issue closed, its stash is done. Every open issue by default; Settings → Stash → Issues as stashes keeps it to yours, or off.
  • Stash news: new comments on an issue, one closed or reopened, a linked pull request's checks failing, changes asked for, merged: each marked on its row, and those about you counted beside Stash in the sidebar. A pull request failing or asked for changes is fixed in its conversation in a click; a merged one asks whether the stash is done.
  • A stash can be published as an issue: what goes is shown first, local paths and secrets pointed out, local pictures uploaded with it. Merging stashes can close a merged one's issue as a duplicate.
  • A new markdown editor: stashes, markdown previews in the side panel and the chat's input are edited as they read, the marks showing only where the caret is. Tables are edited in their cells: rows and columns added and removed, cells picked, copied and pasted as in a spreadsheet; a link shows a bubble to open, copy, edit or remove it.
  • Customize: skills, rules, commands and subagents open in the markdown editor, edited as they read or as their source; front matter shows as properties, edited as a form.
  • SSH drops lose nothing: after a network hiccup the connection goes back to the same session, its terminals, Claude Code and language servers still running there (kept up to three hours while disconnected), no output lost or repeated; a silent network is noticed within 30 seconds.
  • Going on after the usage limit: on Claude's own account, the model picker has Continue After Limit Reset. On, a conversation stopped at the limit goes on once it resets, even with the computer asleep past it; one due while the app was closed goes on as it opens.
  • The Claude Code CLI, recommended: where Claude Code is installed it is the core by default; a conversation on the built-in core suggests switching, above its input, downloading the CLI in a click, or Not Now.
  • Models: subagents and the Opus / Sonnet / Haiku tiers can use another upstream's models; a model can have its own endpoint (Anthropic, Chat Completions, Responses); an upstream or a model is duplicated in a click; models an upstream no longer lists are removed at once.
  • The minimap: each of your messages is a clear mark on it. The pointer near one snaps to it and shows at once the message and the replies around it; a click goes there.
  • The input: a / starting any word opens the command menu; a command's tag shows its whole description on hover, and Open details opens its file in the side panel. @ finds folders too. File, folder and code chips in the input open what they name.
  • While the agent works, Enter in the empty input sends the first queued message now; background tasks (subagents among them) keep going.
  • A changed file's right click opens it in the browser (HTML), its default app or another editor, shows it in the file manager, or copies its path.
  • The side panel's markdown preview takes pictures and files dropped or pasted in, copied beside the document and linked; a right click shows a link's file in the file manager.

Fixed

  • A conversation switched away from and back to is where you left it, its steps still open.
  • A conversation renamed in Claude Code (/rename) is renamed in the list.
  • With "viewMode": "verbose" in Claude's settings, Stash's polish, the input's polish and commit messages no longer fail.
  • A single ~ (a range such as 10-12~10-16) no longer strikes text out.
  • The markdown preview fills the view, wide tables no longer cut off; zoomed in, a drag in it selects under the pointer.
  • With the side panel at the left and the sidebar hidden, its tabs keep clear of the traffic lights on macOS, and the sidebar's toggle is there too; dragging its edge follows the pointer from the width shown.
  • Go to Definition in a remote project opens the right file on its host.
  • Windows: updating or uninstalling ends the browser extension's host first, no longer failing with "DeleteFile failed; code 5".

1.5.1

Long sessions stay quick

Most of this release does one thing: keep a conversation that has run for hundreds of turns as fast and as accurate as it was at the start. Old tool results are put away and fetched back when needed, a full context folds its middle first and keeps the newest exchange, and a subagent's context is kept apart from the conversation's. Alongside that: session export, approvals that say what they are about, and stricter command safety.

New

  • Export a session: a ZIP of the transcript, the subagents' transcripts and the files kept beside the session, from the chat or with /export in the composer, saved wherever you pick. A file too large, or one past what an export may hold, is left out and counted.
  • Approvals say what they are about: each request carries a risk label (read, write, destructive, credential, network), whether the change can be undone, and where the tool comes from. Destructive and credential ones add why — that a drive's root, a system folder or the home directory is being removed, or that a key or password file is being touched. What was asked and decided goes to an audit log.
  • Browser tools ask even in full access: reading a signed-in page's cookies or localStorage, or intercepting and changing its traffic, is confirmed one call at a time whatever the mode.
  • See what an MCP server offers: a server's row opens to its tools, resources and prompts, and shows its last error whatever its status — enough to tell why it is not working without leaving the chat.
  • Bring in what another conversation said: a message naming a saved conversation (as [Session id: title], which the composer inserts) carries that conversation's newest messages, marked as background rather than instructions. At most three sources, 8000 characters each.
  • What the turn changed, and what it delivered: files handed over show as a card, and the activity strip lists the files the last turn changed apart from what earlier turns left, with their line counts.
  • The phone sees how full the context is: a session update may carry the window, what it holds, where compaction starts and whether it has happened. Older desktops send none, and phones that do not know the field ignore it.

Improved

  • Context management for long sessions, reworked:
    • Old tool results are trimmed before they are cleared: one longer than 8K characters first keeps only its head and tail, which is often enough; only when it is not are earlier groups cleared. A resumed conversation applies the same cuts.
    • Compaction leaves room for the answer: the threshold reserves the model's answer (at most 21K) and 13K for the request, never compacting below half the window. After a summary the newest exchange is kept verbatim, a call always with its results.
    • The model can fold, search and restore its own context with tools the chat does not show — only a notice. Folding rewrites the range it covers, so the prompt cache past it stays.
    • Reminders at the 3rd, 5th and 8th identical call.
    • Tools have a deadline, WebFetch 90 seconds; a large Bash result is kept whole until the context machinery offloads it, with both ends in the placeholder.
  • A subagent's context is its own: each run owns its usage, todos, read files and compaction counter, and its summary no longer enters the parent's context.
  • Failures are told apart: rate limit, overload, context overflow, auth and certificate each say what to do. Small jobs — summaries, titles, classifiers — give up on an overload at once rather than retrying for minutes.
  • An empty answer is asked again: a stream that never said anything is its own kind of failure, retried twice rather than spending the whole budget; a turn that ends with no text and no tool call is retried twice, then warned about.
  • Compaction ratio and headroom can be set globally or per model, and prompt-too-long compaction retries are configurable (default 1).
  • Dangerous commands are judged more strictly: git hard resets, cleans and forced pushes, find -delete, rsync --delete, Windows recursive deletes, and commands wrapped in sudo, env, timeout or xargs. PowerShell's abbreviated parameters (-fo is -Force), & { } call blocks and $( ) subexpressions are read through, and iex (iwr …) — fetched and run — is recognised and offered no always-allow rule.
  • Credential folders and keys are protected paths.
  • A resumed session seeds its read state from the transcript; a host may seed one with seed_read_state.
  • A tool call's input is no longer kept once its result is in: a Write's whole file, an Edit's two strings. Only a background command's, a subagent's and a plan's are read again.
  • Search starts from the conversations that can match, through an in-memory index; a query it cannot narrow is scanned as before, so no hit is lost.
  • Auto mode works on another provider's model: where Claude Code's own classifier does not run, BaoCode judges the action with the provider's small model, and the CLI is told to ask.
  • A resumed session no longer overwrites the approval picked here, and the mode is re-sent when the model changes.
  • Auto mode warns about allow rules that would bypass it, and a rule that would allow every command (Bash(bash:*)) is no longer offered as always-allow.
  • Enhance works in an empty project: with nothing to name there, the model used to write a plan instead of the message and be turned down as too long, without a second try. It is now asked again without the project.

Fixed

  • Search and session listings stay quick on very long transcripts (only the ends are read).
  • A subagent's card keeps its latest 200 steps and says how many it left out.
  • A proxy turned on or off mid-session reaches the CLI at once.
  • Compaction stops after three failures in a row instead of spinning.
  • Full access is really full access on Windows: there is no root to be there, so the CLI is no longer needlessly held at Accept edits.

1.5.0

Easy SSH

Connecting to a server no longer starts with setting up ssh in a terminal: type its address in BaoCode and connect, with the password, key and jump host in one form, and no terminal to accept the server's key the first time. Settings has a new SSH Servers page, where all your servers are kept, each with the core it runs.

New

  • Add an SSH server: Add SSH Server… in the list of remote projects asks for the host, port and user, and how to sign in: a password, a private key, or Automatic (as ssh does in a terminal). A pasted user@host:port is split up, the keys in ~/.ssh are offered, and a password is kept in the system keychain. Saved, it connects in one click; a failed connection's page and the sidebar edit it too.
  • Jump hosts: pick a saved server to connect through, each asking for its own password.
  • A server connected to for the first time has its key remembered by itself. One whose key changed is told as such, and once you know it was reinstalled, its old key can be removed to connect again.
  • Settings → SSH Servers: the servers added in the app and the hosts the sidebar has used, to edit, connect, disconnect or remove; the hosts of ~/.ssh/config are listed apart, their file a click away.
  • A core for each server: Automatic (the server's Claude Code CLI if it has one, else the built-in core), the built-in core, or the Claude Code CLI (installed there if missing). Remote hosts no longer follow this machine's core setting.
  • Passwords on Windows 10: the installer carries a recent OpenSSH, used where the system's is too old or missing.
  • Settings → About: the version, the site, the changelog and the issues, and a way to star BaoCode on GitHub. Accounts is now Git Accounts.
  • The browser extension works on Linux, in Chrome, Chromium, Edge, Brave and Vivaldi.
  • A file another tool asks BaoCode to open as file:line:column (a front-end inspector's Open in Editor, say) opens at that line and column.

Improved

  • Typing in the IDE is smoother: an edit goes through only the lines it changed, the input method is given only the lines around the caret, and typing no longer redraws the whole IDE.
  • Switching chat tabs in the IDE is faster: the chats seen last are kept, shown again at once where you left them.
  • Changes in the side panel open in the IDE's diff editor: the deleted code in the text where it is narrow, side by side once wide enough, with the overview of the changes at the right, and long files no longer slow it down.
  • The live time, speed and tokens under a reply while the agent works are one switch now (Settings → General).
  • Through OpenCode's gateway, the requests of a conversation hit its prompt cache: faster, and cheaper.
  • The model menu opens scrolled to the model in use.

Fixed

  • A picture zoomed in the preview is no longer clipped to its first size.
  • Generated images, screenshots and pictures read stay in a conversation switched away from and back to.
  • After switching to another provider's model mid-conversation, messages go to the model picked; with the model in use removed, the one the picker shows is used rather than "Not logged in".
  • Go to Definition (F12) centers its target, even one already on screen.
  • Windows: zoomed in, the title bar's buttons are clickable all the way to their right edge; installing language servers no longer fails with "not a valid Win32 application".
  • The file manager is called by each system's own name (Finder, File Explorer…).

1.4.0

Hello, Linux

BaoCode runs on Linux now: a package for Ubuntu and other Debian-based distributions, x64 and arm64, that keeps itself up to date like the Mac and Windows apps. And setting up a model the first time is a welcome rather than an error.

New

  • Linux: download the .deb for your processor from baocode.dev/download (Ubuntu 22.04 or later, and other Debian-based distributions). It opens folders and files with the system's dialogs, has the system's right-click menus, and pastes text, files and pictures. Thanks to qyh1221, whose port this is.
  • Linux updates itself: a new version is downloaded and checked as on the other systems, then installed once you enter your password, and BaoCode opens again. A copy run from the tarball is pointed to the download page instead.
  • Setting up a model: with no model to run on yet (BaoCode's own core, before any upstream is added), a welcome explains what an upstream is and adds one in a click, opening its page in Settings → Models. The conversation starts by itself as soon as a model is there, with no retry. Until then, Set Up a Model sits in the model picker's place under the input, and in the command palette.
  • From your phone, Start on a plan the agent put to you starts it, as the desktop's button does.

Improved

  • An upstream's models are listed by name, in its settings page, the fetched list and the model picker.

1.3.0

Good Friends with Chrome

This release is about the browser: agents can use your own Chrome now, opening pages, clicking, typing and debugging with your sign-ins, every step of it in view in the side panel. Agents can also make pictures with your upstreams' image models, and pictures show right in the chat. BaoCode has a core of its own; an agent's changes can be reviewed part by part beside the chat; long conversations open faster, and the mouse wheel keeps up with your hand. And a batch of problems is fixed.

New

  • The browser: add the BaoCode extension (from the Chrome Web Store, or as a zip loaded unpacked) and agents can open pages, read them, click and type in your own Chrome, Edge, Brave or Arc, signed in as you are. They touch only the tabs you share with them (the BaoCode button in the browser's toolbar shares the tab you're on). The side panel shows the page they're working in as it happens, and you can work in it too. Turn it on or off and install it in Settings → Browser, on macOS and Windows.
  • Debugging in the browser: agents read the console and network requests, set breakpoints and step through code, see variables by their source-mapped names, find a page's React and Vue components and event handlers, look into performance, memory and unused CSS, block, mock and rewrite requests, and run a tab as on a phone or a slow network.
  • A debugging history of the browser: the pages, requests and console errors and warnings of the tabs you share are kept as they happen, with no recording to start. Say "saving just failed" and the agent looks it up itself. Detailed history keeps request and response bodies too, and your clicks and typing (never passwords). It stays on this computer; Settings shows how much room it takes and clears it, and you're told once it passes 1 GB.
  • Show the agent how: an agent can ask you to do something once in the browser, keep each step as a file in the project, and do it again in your browser later.
  • Making pictures: agents generate images with your upstreams' image models (the Images API, chat interfaces such as OpenRouter's and Gemini's, Codex's gpt-image-2). Pick the default image model in Settings → Models, or Ask each time to choose in the chat; image models stay out of the chat's model picker.
  • Pictures in the chat: what a tool returns as a picture (an image file read, a browser screenshot, an MCP tool's image) and local images in a message show in the conversation. Click one to see it whole, and ← → go through every picture in the chat; right-click to open it in the side panel or the IDE, copy its path or show it in Finder. Image files open in the side panel too.
  • The built-in core: BaoCode's own Claude Code core, with CLAUDE.md, skills, subagents, commands, hooks, plugins and MCP servers, on remote hosts too. Switch in Settings → General → Claude Code → Core: the CLI where Claude Code is installed, the built-in core otherwise. The built-in core uses only the upstreams added in Settings → Models; pick the CLI for a Claude subscription.
  • Reviewing changes beside the chat: the side panel's editor shows an agent's pending changes in the code, as the IDE does, each part to undo or keep on its own. The bar above goes to the previous and next change and keeps or undoes a file, or everything at once. The side panel's editor finds and replaces too.
  • Live usage: while an agent works, the time so far, the writing speed and the tokens roll by under the status line; a finished turn shows its time, speed, cost and tokens, still there when the session is opened again.
  • The status line's musings are now mostly about the step just done, its command or file by name.
  • Polish in the composer: the button beside the context ring has the model tidy your words, keeping tags, images, code and paths as they are, and it can be undone. Turn it off in Settings → General if you don't need it.
  • The side panel can move to the conversation's left: the button in its bar, or Toggle Side Panel Position in the command palette and the View menu.

  • Open a folder on a Linux host over SSH, as with VS Code’s Remote-SSH: the window stays on your machine, and files, search, Git, terminals, language servers and Claude Code run on the host
  • Pick a host from ~/.ssh/config, or type user@host
  • Claude Code is installed on a host that has none, and your models work there too
  • Reconnects by itself; when a host can’t be reached, you’re told why and can retry

Fast IDE

  • An editor, a terminal and Source Control with a commit graph and Git blame
  • Your VS Code themes, keybindings and language servers
  • Markdown files open as a preview you can edit in place, Typora’s way
  • Commit messages drafted by Claude Code, for you to edit and commit

Models and extensions

  • Use other models through Claude Code: Anthropic’s API, OpenAI’s Chat Completions or Responses, with API keys kept in the system keychain
  • Choose the model for each part of Claude Code’s work, and for titles and commit messages
  • Plugins, MCP servers, skills, subagents, rules, commands and hooks in one place, with your skills from claude.ai

Around the app

  • Notifications, a sound and a count on the app’s icon when an agent needs you; agents keep running in the menu bar or tray when the window is closed
  • Open a folder in BaoCode from Finder or Explorer, and keep a window on top of others
  • In English and Chinese
  • Updates itself in the background, and asks before restarting
